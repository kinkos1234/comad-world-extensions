# 반응형 실렌더 체크 — 설계안 (2026-08-16)

결정 큐 `20260816T002958-media-css-pre-push-warn-css-2` 의 대안. 원안은 "`@media` 소스 순서를
정적 검사해 pre-push WARN" 이었고, **판정 수단이 약해 보류**했다. 이 문서는 그 자리를 대신할
설계다. 승인 전 초안이며 아직 구현하지 않았다.

## 왜 소스 순서 검사를 버리나

관측된 사고는 두 건이다.
- one-k-web `f72f837` — Tailwind `relative` 가 `fixed` 를 이겨 폭이 0 으로 붕괴
- ph-tools `3e4ee62` — `@media` 블록을 스타일 앞에 둬서 **반응형 규칙이 통째로 안 먹음**

둘 다 "같은 특이도면 뒤가 이긴다"는 같은 원인이다. 그런데 소스 순서를 정적으로 읽는 검사는
세 곳에서 무너진다.

1. `@layer`·Tailwind 빌드·CSS-in-JS 에서는 **소스 순서가 최종 순서가 아니다.**
2. "같은 셀렉터의 기본 규칙보다 앞이냐"를 알려면 셀렉터를 파싱해야 한다. grep/awk 로는 부정확하다.
3. 정당한 배치가 흔하다 → 오탐이 붙고, 오탐이 붙으면 사람이 무시하고, 그 순간 검사가 죽는다
   (`rules/guard-scope-discipline`).

**핵심은 이것이다: 규칙이 안 먹으면 레이아웃이 깨지고, 깨진 레이아웃은 렌더에서 즉시 드러난다.**
원인(소스 순서)을 추적하는 대신 **결과(깨짐)** 를 재면 프레임워크에 무관하게 판정이 선다.

## 무엇을 재나

한 페이지를 3개 폭(375 · 768 · 1280)에서 렌더하고 세 가지를 센다.

| 지표 | 판정 | 잡는 사고 |
|---|---|---|
| `documentElement.scrollWidth ≤ clientWidth + 1` | 실패 시 FAIL | 가로 스크롤 발생 = 반응형 미적용 |
| 인터랙티브 요소(`input·select·button·a`)의 `getBoundingClientRect().width ≥ 24` | 실패 시 FAIL | **폭 0 붕괴** (ph-tools 입력칸 사례) |
| 요소의 `scrollWidth > clientWidth + 1` 인 텍스트 노드 수 | 임계 초과 시 WARN | 잘린 라벨·버튼 글자 쪼개짐 |

**의도적 가로 스크롤은 자동으로 제외된다.** `overflow-x:auto` 컨테이너 안의 넓은 표는 문서
`scrollWidth` 를 늘리지 않는다. 예외 목록을 손으로 관리하지 않아도 되는 게 이 지표의 장점이다.

## 어떻게 재나 — macOS 함정 하나

`--window-size=390` 을 줘도 **macOS 크롬은 창 최소폭이 약 485px 라 그 아래로 안 내려간다.**
2026-08-15 에 "390px 로 찍었다"고 한 스크린샷이 실제로는 485px 였다.

우회는 **같은 오리진 iframe**이다. 폭을 고정한 iframe 안은 진짜 375px 뷰포트이고, 부모에서
`contentDocument` 로 위 지표를 그대로 잴 수 있다. 이 방법으로 어제 스코어보드·스튜디오·브릿지의
`scrollWidth == clientWidth` 를 확인했다.

## 어디서 도나 — pre-push 가 아니다

브라우저를 띄우는 검사를 pre-push 에 넣으면 느리고(수 초~수십 초) 서버 기동에 의존해 불안정하다.
그런 게이트는 곧 `--no-verify` 로 우회된다.

- **작업 중 명시 호출** — UI 를 만지는 동안 직접 돌린다.
- **증거로 제출** — 결과 JSON 을 `.qa-evidence.json` 의 `checks.responsive` 로 넣는다.
  UI 변경 push 는 이미 `task-quality-gate` 가 시각 증거를 요구하므로, **강제는 기존 게이트가 하고
  이 스크립트는 그 증거를 만드는 도구**가 된다. 새 차단 지점을 만들지 않는다.


## 한계 — 미리 적어둔다

- **로그인 뒤 화면**은 세션이 필요하다. 스텁 서버로 API 를 대신 채우는 방식(2026-08-15 ph-tools 에서
  쓴 것)이 현실적이다. 이 스크립트가 세션을 다루게 만들지 않는다.
- **동적 렌더 타이밍** — 고정 대기는 불안정하다. 특정 셀렉터 등장을 기다리는 옵션이 필요하다.
- **시각적 추함은 못 잡는다.** 이 검사는 "깨졌나"만 본다. 미감은 comad-taste 6축 루브릭 소관이다.
- 폭 0 붕괴 임계(24px)는 근거가 약하다 — 실제 사례를 몇 건 모아 조정해야 한다.
